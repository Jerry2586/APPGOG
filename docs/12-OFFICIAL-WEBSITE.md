# APPGOG 第十二阶段：可编辑官网

状态：代码完成，真实业务资料待产品负责人提供后逐页核实、清除门禁并发布  
方案版本：1  
日期：2026-09-01

## 1. 结论

官网不是硬编码页面。后台一次性创建 21 个独立 Page/PageVersion 草稿；每页仍由已注册 JSON 组件树组成，可继续拖拽、预览、保存、版本回退、下线与发布。初始化操作不会覆盖同名草稿或已发布路由，也不会自动发布页面。

21 项包含需求基线 SITE-001–SITE-016、独立增值商城，以及登录、注册、套餐购买、用户面板和工单普通跳转入口。节点详情使用嵌套路由 `/nodes/detail`，可复制当前草稿继续建立更多节点详情页。

## 2. 页面与入口

| 要求 | 路由 | 页面结构 |
|---|---|---|
| SITE-001 | `/`（数据库 slug 为 `home`） | Hero、转化入口、首页 AI、优势、3D 地球降级视觉 |
| SITE-002 | `/nodes` | 覆盖示意、节点资料卡、来源与更新时间 |
| SITE-003 | `/nodes/detail` | 面包屑、确定返回 `/nodes`、介绍、资料核验 |
| SITE-004 | `/downloads` | Windows、macOS、Linux、iOS、Android 下载入口 |
| SITE-005 | `/help` | AI、搜索、分类、文档、FAQ、视频和工单降级 |
| SITE-006 | `/about` | 新加坡总部定位、愿景、布局、进一步入口 |
| SITE-007 | `/login`、`/register` | 无登录表单，只展示边界并跳转 Xboard |
| SITE-008–016 | `/company`、`/careers`、`/press`、`/partners`、`/affiliate`、`/enterprise`、`/privacy`、`/no-logs`、`/support` | 对应页脚页面，逐页带真实性或法务核验门禁 |
| SHOP-001–008 | `/shop` | 商品分类、商品组件、独立购物车；不创建订单 |
| 边界入口 | `/purchase`、`/dashboard`、`/ticket` | 品牌过渡页和纯外跳按钮，不提交账号或业务资料 |

全站 Header 与 Footer 的链接进入这些数据库页面；公开页无任何“内置页面回退”。草稿或下线页一律返回 404。

## 3. 真实资料发布门禁

初始页面只含安全的结构说明和已确认边界，不含虚构节点数、延迟、实时负载、在线人数、SLA、审计、媒体背书、合作品牌、机房、招聘职位或联系方式。每个待补资料块有 `publicationRequirement`：

1. 后台预览会显示黄色“待核实”说明，并在属性区汇总到可定位清单。
2. 可以反复保存草稿；只要任意嵌套组件的说明未清空，前端操作和服务端 API 都不允许发布。
3. 服务端返回全部阻断项，不能通过绕开页面编辑器直接发布。
4. 填好正式内容、链接和素材后，由有权限的管理员逐项核实并清空对应说明，再发布明确版本。

这是一道确认流程门禁，不自动判断现实世界事实。清空代表操作者已经依据产品、授权或法务资料完成人工核验。

## 4. 隔离与安全

- APPGOG 官网只读取 APPGOG API 和独立数据库。
- 登录、注册、套餐、面板、工单和联盟申请只接受普通 URL；不允许查询参数、片段、账号信息或令牌。
- 未配置的外跳按钮显示“待配置”，不生成 `href`，避免误跳 `#` 或虚构地址。
- 无日志页不包含虚构第三方审计或无手令声明；隐私页明确区分门户、AI、插件和 Xboard 外部系统。
- `ADMIN`/`SUPER_ADMIN` 才能批量创建官网草稿；`VIEWER` 只能查看；写入逐页审计并在任意失败时整批回滚。

## 5. 响应式与可访问性

- 每页一个 H1；内容卡使用 H2；Header 的折叠菜单 ID 按组件实例唯一。
- 360px 手机隐藏 3D 装饰，菜单可展开；768px 平板下载卡自动单列；桌面展示完整导航。
- 面包屑有语义标签；节点返回按钮优先使用明确 `backUrl`，不依赖浏览器来源。
- 空数据、加载、服务错误、404 分开呈现；服务错误可重试，404 页面设置 `noindex, nofollow`。
- reduced-motion 和低性能设备沿用组件系统降级策略。

## 6. 自动及浏览器验证

- 31 项方案测试：21 页逐页 Schema、SEO、单 H1、Header/Footer、发布门禁，另含完整路由、组件绑定、无虚构地址、嵌套返回及 URL 安全。
- 13 项真实 Nest HTTP/JWT/服务测试：权限、DTO、21 页原子初始化、幂等、路由保护、事务回滚、发布阻断、嵌套路由、线上快照隔离、下线和身份参数拒绝。
- Web 单元测试覆盖嵌套路由参数、嵌套待核实清单和 SEO 清理。
- 本机浏览器验证覆盖 1280×900 桌面、768×900 平板、360×800 手机：首页、下载、帮助、登录、节点详情与后台；无横向溢出、无控制台错误、无外联资源。

## 7. 发布前仍需提供的真实资料

- Logo、字体、品牌图片、正式域名及 SEO 分享图；
- Xboard 登录、注册、套餐、面板、工单、联盟营销正式 URL；
- 各平台客户端名称、授权、版本、系统要求、下载地址和教程；
- 可公开节点、资料来源、核验日期及更新方式；
- 公司正式主体、注册地址、品牌故事、招聘邮箱、商务邮箱、Telegram；
- 经授权媒体报道、合作伙伴、设施资料；
- 隐私政策、无日志声明和服务条款法务定稿；
- 真实支持时间、响应规则或 SLA 证据。

在这些资料到位并人工核验前，相应页面应保持草稿。没有资料时明确写“暂无”也优于发布虚构示例。

## 8. 阶段边界

本阶段不包含独立 Xboard 登录后主题。该主题仍属于第十三阶段，必须等产品负责人下一条明确指令，并先确认目标 Xboard 版本及官方主题机制。

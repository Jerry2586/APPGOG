## 3. 菜单与原生路由映射

| 显示名称 | Xboard 原生路由 | 处理方式 |
|---|---|---|
| 仪表盘 | `/dashboard` | 原生路由 |
| 使用文档 | `/knowledge` | 原生路由 |
| 流量商店 | `/plan` | 原“购买订阅”的易懂别名，不改接口 |
| 我的套餐 | `/dashboard?section=subscription` | 定位原生仪表盘订阅卡，不复制套餐数据 |
| 我的订单 | `/order` | 原生路由 |
| 我的邀请 | `/invite` | 原生路由 |
| 个人中心 | `/profile` | 原生路由 |
| 我的工单 | `/ticket` | 原生路由 |
| 流量明细 | `/traffic` | 原生路由 |
| 节点状态（辅助入口） | `/node` | 保留目标版本已有功能，避免换肤造成能力丢失 |

导航采用顶部横向结构；桌面完整展示，窄屏允许导航自身横向滚动，不让整个页面横向溢出。登录后底部只有 `© APPGOG` 和“会话与业务数据由 Xboard 原生机制管理”，没有官网大型 Footer，也没有虚构 TLS、SLA、无日志或在线状态。

## 4. 完全隔离边界

- APPGOG 门户代码仍不导入 `Xboard-master` 或独立主题；根边界守卫已新增反向依赖检查。
- 主题增强层不调用 `fetch`、XHR、WebSocket 或 EventSource，不读取/写入 Cookie、LocalStorage、SessionStorage、Token 或用户映射。
- 主题不请求 APPGOG API，不连接 APPGOG 数据库，也不让 APPGOG 后端代理 Xboard 数据。
- 主题展示的账号、订阅、套餐、订单、邀请、节点、工单和流量内容全部仍由原始 Xboard 前端及原始 API 处理。
- 未加入活动中心、签到、盲盒、抽奖、地图节点装饰或虚构用户数、节点数、IP、延迟、吞吐、SLA、公司和安全认证事实。

## 5. 安装与切换

推荐先备份目标 Xboard 的数据库、`storage` 与当前主题目录，再在管理后台上传 `APPGOG-theme-1.0.0.zip`，选择 APPGOG 作为前端主题并保存。也可以把源码目录随本源码快照部署为系统主题。上线前必须在测试环境确认回滚到原 Xboard 主题的路径可用。

主题包只有约 0.42 MiB，低于目标源码控制器的 10 MiB 上传上限。包内顶层目录是 `APPGOG/`，包含配置、Blade、样式、增强脚本、同哈希原生业务资产和本地背景 SVG。

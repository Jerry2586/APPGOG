# 第九阶段：独立非流量商品与购物车

日期：2026-08-31。项目名 APPGOG。

状态：本阶段功能已实现；本机验证记录见下文。真实 PostgreSQL/容器迁移、完整目标浏览器和实机验收仍待执行，**不标记为全部上线验收通过**。用户明确授权本阶段，但不据此抹去第八阶段待验项；未进入第十阶段。

## 1. 范围与边界

按正式产品/接口/后台全景线框图、冻结需求 SHOP-001～008 及 CMP-009 实施。与 Xboard 完全隔离，不共享账号、Cookie、Token、API 或数据库，不引入 Xboard 套餐。商品类型只包含非流量账号、定制服务、设备、其他非流量商品。

公开展示继续由已注册的 products、cart、categories 组件及页面 JSON 驱动，编辑器预览与公开页面共用渲染器；没有硬编码商城首页或增加结算页。商品详情使用组件内对话框。SEO 字段可编辑并随商品发布；不把详情对话框称为独立可索引 SEO 页面，页面 SEO 仍由页面引擎管理。

## 3. 操作与一致性约定

- 后台选择“独立商品库”新建，填写资料并保存草稿；确认发布后前台可见。保存已发布商品的新草稿不会立即覆盖线上价格、库存、销量、分类、详情或链接。发布操作使用保存后的 baseRevision。
- 库存与销量由运营手动维护，显式发布后生效；外跳点击不扣库存、不加销量、不预留库存。最终外部交易价格、购买数量和交付由外部网站确认，APPGOG 无法核实外站实时库存。
- 购物车每种商品收录一次，最多 100 种，不添加数量/合并结算机制。参考金额使用整数分计算，按币种分别汇总，不自动换汇；已售罄/失效商品不计合计。
- 新持久化键 appgog_catalog_cart_v1 只保存 `{version:1,ids:[...]}`。兼容读取旧 appgog_cart 的商品 ID，不相信旧缓存价格或链接；写入新键不复制旧资料。存储被禁时可在当前页面会话使用，并显示提示。
- 购物车在首次挂载、页面聚焦、手动刷新及挂载期间每 60 秒读取公开商品。核验中或失败时暂停外购入口；下架/不存在项提示移除，售罄项保留展示但不可购。不是服务端推送，运营变更到下一次核验之间仍有刷新间隔；外站也必须独立校验最终交易。
- 商品 Markdown 禁原始 HTML 执行，服务端白名单清理，前端 DOMPurify 二次防护。图片 URL 与外购 URL 校验分离；媒体库继续沿用第七阶段安全上传，不新增外部抓取/图片代理。
- 商品、商品分类与审计同一串行化事务；陈旧版本、重复 slug/SKU、并发冲突返回 409。分类删除检查草稿和保留的公开商品快照，不能绕过线上引用。
- VIEWER 只能查看；EDITOR 可创建、编辑、发布、下架；归档/恢复最低 ADMIN。离开后台商品编辑、切换菜单或刷新有未保存保护。

## 4. 组件使用示例

下列为页面布局中的组件，不是额外固定页面。实际分类 ID 通过属性面板选择，不填写示例假 ID：

```json
[
  {"id":"catalog-categories","type":"categories","props":{"title":"商品分类","scope":"PRODUCT"}},
  {"id":"catalog-products","type":"products","props":{"title":"独立商品","categoryId":"","sort":"salesDesc","limit":8,"columns":4,"cardStyle":"glass","hoverEffect":"lift"}},
  {"id":"catalog-cart","type":"cart","props":{"title":"购物车","position":"bottom-right"}}
]
```

购物车可选 bottom-right、bottom-left、inline。分类组件 PRODUCT 使用 productCategory 查询参数，和 CMS 的 category 参数隔离；商品组件以分类树当前选择优先，否则使用组件配置的分类。没有选择分类时查询全部已发布商品。

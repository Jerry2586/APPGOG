## 1. 阶段边界

本阶段只做全量验证、缺口修复、可重复部署、备份恢复和需求签收，不新增需求。APPGOG 与 Xboard 继续完全隔离：无 SSO、无共享 Cookie、无 Xboard API、无 Xboard 数据库连接、无业务数据同步。独立 Xboard 主题仍是单独制品，不由 APPGOG 后端加载。

本项目最初冻结为 14 个阶段，因此本阶段结束后没有“第十五阶段”。生产环境条件未满足时应继续执行本文件的环境验收清单，不得另立一个阶段绕过未验项。

## 5. 可重复部署

1. 在只部署 APPGOG 的目录复制 `.env.docker.example` 为 `.env`，生成数据库密码、至少 32 位 JWT 随机密钥和至少 16 位管理员强密码。不要复用 Xboard 的任何密钥、网络或数据库。
2. 填写正式 HTTPS Origin 和经过确认的普通 Xboard 页面 URL。跳转 URL 不得带查询参数、片段、Token 或用户 ID。
3. 先执行 `docker compose config`，确认输出中只有 APPGOG 的 `init/api/web/postgres/redis` 服务。
4. 执行 `docker compose build --pull`，再执行 `docker compose up -d`。`init` 会先执行 Prisma 迁移和幂等种子；成功后 API 才启动。
5. 执行 `docker compose ps`，确认 API 的 `/api/v1/health/ready` 为 healthy，再访问 Web 的 8080 端口和 API 的 3000 端口。
6. 首次登录后立即修改管理员密码并确认旧会话已撤销。

PostgreSQL 和 Redis 只挂在 `appgog_private` 内部网络，不暴露 5432/6379 到宿主机。Web 与 API 只共享 `appgog_edge`。Compose 不声明、加入或依赖任何 Xboard 网络。

## 6. 备份、恢复和演练

- 备份：`sh deploy/backup.sh`。输出为 PostgreSQL custom dump，并生成 SHA-256 校验文件；应加密复制到异机或对象存储。
- 非破坏性演练：`sh deploy/backup-restore-drill.sh`。它创建固定临时库 `appgog_restore_drill`，恢复并核对核心表后删除临时库，不覆盖正式库。
- 正式恢复：`APPGOG_RESTORE_CONFIRM=APPGOG_RESTORE sh deploy/restore.sh backups/<文件>.dump`。脚本先创建恢复前快照，再停止 API、校验并清理恢复、重跑迁移/种子、启动 API 和检查就绪。
- 建议至少每日备份、每月演练；保留周期、加密和异地副本必须按正式运维策略确定。媒体卷 `appgog_media` 需要由宿主机/存储平台另行做一致性快照，数据库备份不能代替媒体文件备份。

恢复是破坏性操作，只能由明确授权的运维人员在已确认目标主机和备份文件后执行。脚本的确认变量不能替代人工变更审批。

## 7. 正式环境最终放行清单

当前工作站未安装 Docker、PostgreSQL 客户端或 Safari，且没有正式域名、数据库、模型密钥和运营资料。因此以下项目保持环境待验，任何人都不得将其改写为“已通过”：

- 在目标 Docker 主机执行 `docker compose config/build/up/ps` 和 API/Web 健康访问。
- 在目标 PostgreSQL 数据上执行迁移、种子、备份和非破坏性恢复演练。
- 对 `appgog_media` 做真实快照与还原抽查。
- 在 Safari 实机验证原生 HLS，在当前支持的 Chromium/Firefox 验证 Hls.js 回退。
- 配置正式 AI 服务后验证向量维度、调用额度、引用和降级；不得把密钥放入浏览器。
- 逐页填写并核验正式公司、联系、下载、媒体、合作伙伴、节点和法务资料，清除发布门禁后再发布。
- 从部署主机抓取网络记录，确认无 Xboard API、数据库、Cookie 或身份数据交换。

只有上述条件也留下可复核证据后，才能把“条件通过”改为“通过”并宣布生产验收完成。

## 8. 追加要求：跨面板安装向导

产品负责人在第十四阶段验收后追加了安装向导要求。该功能不改变原 115 项冻结需求，也不建立新阶段；作为部署入口纳入现有 `pnpm verify`：

- 支持宝塔、1Panel、aaPanel、标准 Docker 和纯 SSH Linux。
- 五步界面覆盖安全 Token、环境预检、独立配置、隔离复核和部署健康检查。
- 安装 Token 使用常量时间校验，只保护一次性安装接口；无 Xboard Token 字段。
- 默认回环监听，远程监听需显式授权；无外部 CDN，可通过 SSH 转发离线访问。
- 服务器随机生成数据库密码和 JWT 密钥；已有 `.env` 拒绝覆盖，成功后完成锁拒绝重装。
- 部署只执行固定参数的 Docker Compose 命令，`shell=false`，不接受浏览器提交的 Shell。
- 自动测试覆盖五种面板、HTTPS/URL 边界、密钥隔离、错误 Token、完整 dry-run 和完成锁。
- 浏览器以 1280px 完成错误/正确 Token、1Panel、配置、复核、保存、五步部署与完成页；以 360px 验收首屏和面板网格。发现并修复 5px 横向溢出后，页面级横向溢出为 0，控制台无错误。

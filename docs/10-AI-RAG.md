# 第十阶段：AI 知识库、文档投喂与全局客服

## 1. 范围与结论

按需求冻结基线 AI-001～AI-012、CMP-013～CMP-014 实现本阶段。APPGOG 与 Xboard **完全隔离**：不共享账号、会话或数据库，不查询 Xboard 订单、余额、套餐、流量，不代建工单；只允许无身份参数的普通工单 URL。

本阶段提供真实模型网关、持久索引队列、向量/关键词混合检索、引用约束、专用后台与前台组件。外部模型默认关闭；未配置时明确降级为关键词文档搜索，不能把该状态称为“已启用语义模型”。投喂指检索增强（RAG），不是对模型训练或微调。

代码、本机自动测试与隔离浏览器验收分别记录于下文。真实 PostgreSQL/pgvector、容器、外部模型效果和实机验收仍待执行，不能据本地替身测试宣布可直接上线。本阶段结束后停止，等待用户指令才进入第十一阶段。

## 3. 后台操作与一致性

主菜单“文档投喂 / AI 客服”提供：服务与全局开关、自动入队开关、召回数量、相似度门槛、访客/全站每分钟上限；可查看服务端配置状态、今日调用额度、待处理/运行/失败任务、可投喂文档与分块数量。已配置仅表示环境字段有效，不代表连通性验证通过。

- VIEWER 可读；EDITOR 可切换文档投喂、重试失败任务；ADMIN 可按批重建；SUPER_ADMIN 才能保存全局 AI 设置。所有入口仍经过真实管理员 JWT/RBAC。
- 设置采用完整快照和 baseRevision 乐观版本，审计与更新同一串行化事务，冲突返回 409。页面自动刷新任务不覆盖未保存设置；离开菜单/页面及浏览器刷新有未保存保护。
- 每篇投喂开关也检查内容 baseRevision。关闭时立即删除该来源分块、清空索引时间、取消 PENDING/RUNNING；未发布草稿即使允许投喂也不入队、不检索。
- 发布不等待外部模型：先原子提交新公开快照及索引任务，响应 PENDING。CMS 编辑器可单独刷新最近索引状态，不丢失编辑中的草稿。
- 同一文档同一哈希/配置只保留一个活动任务。每 5 秒处理一个任务，每进程禁止任务重入；数据库 Serializable + 条件更新认领，租约 10 分钟，过期可恢复。提交前同时核验租约、公开状态、内容哈希及模型指纹。
- 索引失败最多自动尝试 3 次，间隔约 10 秒、20 秒；已建好的同版本分块在失败事务回滚后保留。终态失败须人工重试，后台对账不会无限重复消耗模型额度。
- 自动对账每分钟最多扫描 50 篇，通过 ID 游标分批补齐索引。关闭“自动入队”只停止发布时自动入队及自动补齐，不取消已存在的任务、不阻止手动投喂/重建。处理器暂停需服务端 AI_WORKER_ENABLED=false 并重启；暂停期间任务保留。
- “从头提交一批”最多 100 篇，按 ID 升序返回 nextCursor；有下一批才显示“继续下一批”，不会把首批成功误报为全库完成。失败批次已经成功入队的任务保留，重试通过活动任务去重；请求有审计记录。
- 文档草稿标题可在后台查看，但引用、分块、搜索只使用公开快照。前台已经显示的回答不会被服务器远程擦除；下一次请求重新校验，运营关闭之后不会在新响应中继续授权引用。

## 4. 检索与模型安全边界

输入去首尾空格并做 NFKC 标准化，1～2000 字符，拒绝非法控制字符。请求不接受会话历史、系统提示、模型地址、密钥、客户端引用资料或 Xboard 用户 ID。

检索使用数据库先筛选匹配词的公开资料（最多 200 个候选），再按标题/正文词得分排序，不是先取固定前 100 篇。配置模型时额外嵌入问题，查询相同 indexProfile 的向量，过滤 contentHash 与当前公开哈希不一致的数据。语义最多取 6×topK 个分块（上限 60），按文档去重，再与关键词融合取 topK。最低相似度仅作用于语义分支。最终资料集最多 10 篇，每篇给模型最多 1800 字符。

只接受配置的服务端 HTTPS 443 模型端点；拒绝 URL 凭据、查询和片段、内网/保留地址。DNS 返回的全部地址须通过公网检查，并把校验后的地址固定到 TLS 请求中，阻止重新解析绕过；不跟随重定向。网关仅能 POST embeddings 或 chat/completions，不抓取文档链接、不提供任意 HTTP 工具。DNS 超时 5 秒，模型请求超时 15 秒、无 SDK 自动重试；请求体最多 512 KiB，响应最多 2 MiB。

向量必须为 1536 个有限数值且非全零，逐项核对响应下标与数量。对话通过现有 OpenAI SDK 发起，store=false、JSON 输出格式、max_completion_tokens=1500；长度截断或异常结束不作为完整答案。只接收 1～6000 字符答案、布尔 unresolved 和最多 10 个已知 sourceIds；剥离 HTML/脚本及外部地址，前端再以文本插值呈现，不执行模型内容。

基础检测阻止常见改写系统规则、窃取提示词/密钥、带 Token 的地址及私人账号查询。**检测不是完备的提示注入防火墙**，不能保证识别所有绕过或证明答案完全正确；还依赖无工具能力、公开来源隔离、引用校验、额度控制及人工核对。界面明确提醒勿输入密码/Token/私密订阅地址。APPGOG 不持久保存问答正文或聊天历史；服务端限流仅保存每分钟 HMAC 地址标识和计数，不记录原始访客地址。外部模型启用后会收到用户问题和选取的公开知识资料，运营方需确认其服务条款及数据处理要求；store=false 不等于第三方绝不保留任何日志。

官方文档复核使用了 OpenAI Docs 技能，影响包括输入/输出边界、结构化受控上下文和向量维度/响应校验；没有迁移现有 SDK、调用真实付费模型或宣称通过真实模型效果验证。参考：[OpenAI 安全实践](https://developers.openai.com/api/docs/guides/safety-best-practices)、[Embeddings 创建接口](https://developers.openai.com/api/reference/ruby/resources/embeddings/methods/create)。

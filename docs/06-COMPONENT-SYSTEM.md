# APPGOG 第 6 阶段：版本化组件系统

版本：1.0  
状态：第 6 阶段代码完成，等待产品负责人验收  
依据：`docs/01-REQUIREMENTS-BASELINE.md` 中 CMP-001～CMP-018、NFR-005

## 1. 实现结论

第六阶段建立了一套服务端权威、前后台共用的组件契约。页面编辑器不再保存自己的静态组件清单；它从受 RBAC 保护的 `/api/v1/admin/components` 读取 Schema v1 清单，并按字段类型生成输入控件。页面预览和公开站点共用同一个前端渲染注册表。

当前有 18 种可拖入页面的注册组件：`grid`、`hero`、`carousel`、`button`、`header`、`footer`、`breadcrumb`、`products`、`cart`、`categories`、`contents`、`faq`、`ai`、`sale`、`popup`、`countdown`、`particles`、`globe`。全局 AI 客服是站点级组件，不允许重复拖入页面树。

## 2. 单一组件契约

每个定义包含：

- 唯一 `type`、中文名称、组件分组和是否为容器。
- `dataDependency`：`NONE`、`CMS`、`CATALOG` 或 `AI`。
- 完整默认 Props。
- Props 字段、控件类型、枚举和数值范围。
- 独立的组件 Schema 版本，当前为 1。

服务端在页面创建、保存、发布和回退时重新验证 Props。未声明属性、错误类型、非法枚举、越界数字、危险 URL 和嵌套对象中的危险 URL 都会被拒绝，不能通过手写请求绕过编辑器。

## 3. 编辑器与渲染一致性

- 组件库分组、名称、默认值和属性面板全部来自服务端清单。
- JSON 类型属性在编辑器中先解析，格式错误不会写入画布历史。
- `BlockRenderer` 只负责从注册表选择渲染器；具体行为拆到网格、Hero、按钮、站点结构、轮播、数据、营销和动效渲染器。
- 编辑画布预览与公开页面导入同一份 `componentRenderers`，避免“后台看得到、上线变样”的双实现漂移。
- 未知组件显示明确错误占位；服务端正常情况下会在保存前拒绝未知组件。

## 4. 无障碍和性能降级

- 键盘焦点统一使用可见 `focus-visible` 样式。
- Header 提供语义导航、移动菜单的 `aria-expanded` 和可访问主题切换名称。
- 面包屑使用 `nav`、有序列表和 `aria-current`。
- 轮播支持按钮、圆点、触摸滑动、悬停/聚焦暂停、当前项播报，并在用户要求减少动画时停用自动播放。
- FAQ 使用原生 `details/summary`。
- 弹窗使用 `role=dialog`、`aria-modal`、初始焦点、Tab 循环和 Escape 关闭。
- 图片使用延迟加载和替代文字；数据接口失败显示可理解的降级信息。
- 粒子和地球在减少动画、低并发 CPU、低质量配置及移动端禁用配置下自动降级，不阻塞主要内容。

## 6. 自动验证

- `pnpm verify:components`：检查 18 个服务端定义与 18 个前端映射一致、编辑器使用远端 Schema、共享渲染、轮播无障碍、动效降级和全局 AI 开关。
- API 单元测试覆盖所有默认 Props、清单唯一性、未知字段、非法枚举、越界数值和嵌套危险 URL。
- Web 单元测试检查所有组件均有渲染映射。
- `pnpm verify` 串联数据库生成、全部静态守卫、类型检查、生产构建和测试。

第六阶段不新增数据库表，因此没有伪造迁移执行结果。当前工作区仍没有可用 PostgreSQL/Docker；真实数据库部署与浏览器端到端验收必须在提供运行环境后执行。

第 6 阶段在此停止；未收到明确指令前不进入第 7 阶段。

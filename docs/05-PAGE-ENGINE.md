# APPGOG 第 5 阶段：零代码页面引擎

版本：1.0  
状态：第 5 阶段已完成，等待产品负责人验收  
依据：`docs/01-REQUIREMENTS-BASELINE.md` 中 PAGE-001～PAGE-014

## 1. 实现结论

第五阶段已把页面从通用 CRUD 原型中拆出，建立专用的页面接口、不可变版本、唯一线上路由索引、严格 JSON 树校验、可视化递归拖放、预览、撤销恢复和历史回退。

本阶段只实现页面引擎核心，不提前宣称后续阶段的每个业务组件已完整验收。

## 2. 草稿与线上完全分离

`PageVersion` 是不可修改的完整快照，包含：

- 页面名称、slug、路由类型和重定向 URL。
- SEO 标题、描述、关键词和分享图。
- Schema 版本和完整 JSON 组件树。
- 版本号、修改备注、创建者、恢复来源和时间。

`Page.draftVersionId` 指向当前草稿；`PublishedPageRoute` 是公开网站唯一的路由索引，并指向已发布快照。因此，编辑草稿 slug、SEO、重定向或布局都不会改变线上内容，只有显式发布才会替换线上索引。

下线、转草稿或归档会在同一事务内移除线上路由，公开接口立即返回 404。

## 3. 路由与重定向

- slug 自动去除首尾斜杠并转小写，长度 1–200。
- 支持 `help/windows/install` 等多层路由，拒绝连续斜杠。
- `admin`、`api`、`content` 及其子路由是系统保留前缀。
- 草稿 slug 在 `Page` 中唯一，线上 slug 在 `PublishedPageRoute` 中唯一。
- 外部重定向仅允许无 username/password、无查询参数、无 hash 的 HTTP/HTTPS URL。
- APPGOG 仅把该 URL 返回浏览器，服务器不请求 Xboard。

## 4. JSON 树安全 Schema

| 规则 | 限制 |
|---|---|
| Schema 版本 | 当前固定为 1，未知版本拒绝 |
| 组件注册 | 只允许版本化白名单内 18 种类型（第 6 阶段加入 breadcrumb） |
| 组件 ID | 1–100 位安全字符，整页不得重复 |
| 数量/体积 | 最多 500 个组件，JSON 最多 256 KiB |
| 嵌套 | 最多 10 层；仅 `grid` 可包含子组件 |
| 网格 | `columns` 只能是 1–4 的整数 |
| 数据数量 | `limit` 只能是 1–50 的整数 |
| Header/Footer | 只能顶层各一个；加入后 ID 锁定，普通保存/回退不能删除或替换 |
| URL | 站内路径或纯 HTTP/HTTPS；拒绝 `javascript:`、协议相对 URL、身份信息和查询参数 |
| 对象安全 | 拒绝未声明组件字段、非有限数字、过深属性和原型污染键 |

校验在创建、保存、发布和回退时重复执行，不信任浏览器传入的 JSON。

## 5. 并发、版本和回退

- 保存必须提供当前 `baseVersionId`。如果其他管理员已经保存，返回 409，不覆盖新草稿。
- `Page.nextVersion` 通过行更新保留版本号，保存/回退使用串行化事务。
- 发布必须提供当前 `draftVersionId`，过期草稿不能发布。
- 历史版本永不覆盖。“恢复”会创建一个新版本，并保留 `restoredFromId`。
- 创建、保存、发布、状态变更、回退和删除全部写入不可变审计日志。

## 6. 可视化编辑器

- 支持顶层排序、`grid` 递归嵌套和同层/跨容器拖放。
- 属性面板可编辑内容、URL、列数、数据源、数量、页面路由和 SEO。
- 内存历史保留最多 50 个布局快照，支持安全撤销/恢复。
- 未保存标识、页面切换确认和 409 冲突提示避免静默丢失。
- 本地未保存草稿可直接切换桌面、768px 平板和 375px 手机预览。
- 版本列表可把任意历史版本恢复为新草稿。

## 8. 迁移与验证

迁移 `20260829050000_stage5_page_engine` 会：

1. 为页面增加并发安全的 `nextVersion`。
2. 把现有页面元数据回填到每个不可变版本快照。
3. 建立 `PublishedPageRoute` 唯一线上路由和数据库归属触发器。
4. 增加 slug、路由目标、版本号和下线路由清理约束。

自动验证：`pnpm verify:pages` 和 `pnpm verify`。

当前工作区没有可用 PostgreSQL/Docker，因此本阶段只能完成 Prisma 生成、迁移静态约束检查、类型检查、单元测试和生产构建。提供真实数据库后仍必须执行 `pnpm db:deploy` 和真实浏览器/API 验收，不伪造已执行结论。

第 5 阶段在此停止；未收到明确指令前不进入第 6 阶段。

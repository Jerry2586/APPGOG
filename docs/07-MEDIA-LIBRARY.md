## 2. 数据与存储

MediaAsset 保存随机存储键、原始显示名、真实 MIME、扩展名、字节数、SHA-256、宽高、替代文字、文件夹、上传管理员及归档时间。迁移为 `20260829070000_stage7_media_library`，Schema 版本保持 7；本轮不篡改已生成的历史迁移。

- 存储键由哈希分片与随机 UUID 构成，不使用用户文件名作为路径。
- 默认私有目录为 `data/media`；MEDIA_STORAGE_DIR 可指定目录，磁盘根目录被拒绝。
- 根目录和分片目录拒绝符号链接，检查真实路径；读文件拒绝符号链接、非普通文件和多重硬链接。
- 写文件使用 wx 不可覆盖创建，并同步文件内容。读文件先检查大小，再进行最多 10 MiB 的有界读取。
- 管理响应移除 storageKey；公开地址为 `/api/v1/public/media/:id`，不开放磁盘静态目录或目录枚举。
- 每次公开读取都验证字节数和 SHA-256，包括条件 ETag 请求。丢失文件返回 404，完整性/存储异常返回 503，不返回错误图片或长期缓存头。
- 本阶段使用可替换的 MediaStorageService 本地持久卷驱动，没有伪装成已配置的 S3 服务。

文件系统与数据库不是一个跨系统 ACID 事务：先写文件，再事务提交元数据和审计。事务异常后独立查询随机存储键：确认已提交则返回成功；确认无引用才清理；不能确认则保留文件并记录存储键等待对账。进程崩溃或连接不确定可能产生孤立文件，不能无条件删除，不能用归档接口物理清理。

## 3. 上传安全与接口

接口根路径与角色保持 API-CONTRACT.md 的 v1 契约：

| 方法/路径（省略 /api/v1） | 最低角色 | 行为 |
|---|---|---|
| GET /admin/media | VIEWER | 分页、搜索、文件夹及归档状态查询 |
| POST /admin/media | EDITOR | multipart 单图片，字段 file、可选 altText/folder |
| PATCH /admin/media/:id | EDITOR | 修改替代文字/文件夹，不替换文件字节 |
| DELETE /admin/media/:id | ADMIN | 可恢复归档，不物理删除 |
| POST /admin/media/:id/restore | ADMIN | 恢复；接受 {} 或 {restore:true} |
| GET /public/media/:id | 无 | 按 ID 读取已验证图片，归档不使既有 URL 失效 |

安全限制：

- 文件长度 1–10485760 字节，包含 10 MiB 上限；超限返回 413。
- JPEG、静态 PNG、GIF、WebP 白名单；请求 MIME 必须匹配实际内容。SVG/HTML、损坏文件以及只改扩展名的伪图片被拒绝；文件名本身不作为类型依据。
- 签名、结构和尾标只是预检，还必须完整解码像素。原先仅构造 PNG/JPEG 头尾而没有真实像素的文件，现在无法通过上传。
- 动画 GIF/WebP 最多 200 帧、累计最多 4000 万像素；单边最多 30000。APNG 显式拒绝，不能只解码其静态回退帧后放行。
- 每个进程最多同时执行 2 个完整解码；像素解码超时 10 秒。繁忙返回 503，前端明确提示重试。
- 文件夹、替代文字、查询页码、未知字段和显式 null 均有校验。恢复传 false 不会被当作有效请求。
- 原始显示名处理 Windows/POSIX 路径、控制字符和孤立代理字符，避免响应头编码失败。
- 公开响应使用真实 MIME、nosniff、跨域图片策略、一年不可变缓存和 SHA-256 ETag。支持条件请求列表、弱 ETag 和 *，304 不返回实体。

完整解码使用固定版本 sharp 0.34.5。实现依据为其官方 [输入与安全选项](https://sharp.pixelplumbing.com/api-constructor/) 和 [输出解码 API](https://sharp.pixelplumbing.com/api-output/)，而不是仅检查扩展名或 metadata()。

## 4. 权限、审计与生命周期

| 操作 | VIEWER | EDITOR | ADMIN | SUPER_ADMIN |
|---|:---:|:---:|:---:|:---:|
| 查看/选择 | ✓ | ✓ | ✓ | ✓ |
| 上传/修改元数据 | — | ✓ | ✓ | ✓ |
| 归档/恢复 | — | — | ✓ | ✓ |

四类审计事件为 MEDIA_UPLOADED、MEDIA_UPDATED、MEDIA_ARCHIVED、MEDIA_RESTORED。业务变更与审计同事务，审计失败不能独立提交变更。修改/归档/恢复的旧值读取也在串行化事务内部；数据库并发冲突映射为 409，要求刷新重试。重复归档/恢复幂等，不重复记审计。

归档只隐藏默认列表条目，保留公开 URL 和文件；已发布页面不会因归档失去图片。物理删除、对象存储迁移和孤立文件自动清理不属于本阶段普通后台操作，必须先核对引用和备份。

## 5. 后台与页面编辑器

- 媒体库每页 30 条，显示总数、页码、上一页/下一页；不再静默截断为前 100 张。
- 支持上传进度、失败消息、搜索、文件夹/状态筛选、替代文字编辑、URL 复制、归档和恢复。剪贴板不可用时保留可手动复制的只读 URL。
- 列表及选择器忽略过期请求，组件卸载后不写回状态。归档导致末页为空时回到有效页码。
- API/Web 分域时，图片展示、复制和选图地址由 API origin 解析，不错误拼到 Web origin。
- Hero 图片、轮播 slides/images、SEO 分享图接入媒体选择器。旧式换行 URL 列表不会在追加图片时被清空；新轮播项保留替代文字并执行 30 项上限。
- 选图时记录页面和组件 ID；目标切换后拒绝写入，避免污染另一个页面/组件。选图不会自行发布，仍走原页面草稿/版本系统。
- VIEWER 没有上传、修改、归档按钮，后端同时独立拦截越权请求。
- 媒体库后台区域、表单、分页和编辑弹窗适配 360px 手机宽度；选图/卡片按钮明确前景颜色，避免继承全局暗色造成白底白字。

## 7. 部署与待环境验收

- Docker API 保留 pnpm 工作区目录层级和直接依赖链接，确保 Nest/Prisma/sharp 在运行时能够解析；已代码复核，未伪称 Docker 镜像已构建运行。
- API 工作目录仍为 /app，媒体卷挂在 /app/data/media，与默认相对配置一致。
- Nginx /api/ 请求体上限为 11 MiB，预留 multipart 开销；后端仍限制实际文件 10 MiB。自定义 CDN/上级代理也应允许这个请求体。
- Docker 构建上下文排除本地媒体、依赖缓存与环境文件。

提供真实隔离测试环境后必须完成：

1. 安装锁定依赖、执行 `pnpm db:deploy` 和 `pnpm db:status`，确认第七阶段迁移及约束生效。
2. 用真实四角色账号验证上传/修改/归档/恢复；触发并发更新和审计写入故障，确认数据库事务行为。
3. 经部署代理上传四种真实图片以及精确 10 MiB 文件；在前台页面选图、保存、预览、发布并验证历史 URL。
4. 分域配置正确的 VITE_API_URL 和允许的管理来源，验证媒体显示、Cookie 管理认证及缓存响应。
5. 重建/重启 API 容器，确认已上传文件仍存在；缺失/篡改文件时必须失败关闭。
6. 同步备份数据库与媒体卷，在隔离恢复目录复原并抽查哈希。连接异常保留的文件，先按日志存储键核对数据库与备份；有引用的绝不能删除，状态未确认的继续保留。
